## Payloads

| Limit | Value |
| --- | --- |
| Zekt Action request | Up to **1 MB**. Larger requests get HTTP 413. |
| Time Travel archive copy | Payloads over **512 KB** are archived as a placeholder. The event is still delivered normally. |
| GitHub `client_payload` top-level properties | GitHub allows 10. Zekt nests its own fields, so this doesn't limit you. |

Keep payloads small: a few KB of metadata rather than build artefacts.

## Schemas

- At most **64 KB** (UTF-8), and it must be a JSON object.
- Only local `$ref` (starting with `#`), and every reference must resolve. `$dynamicRef` and
  `$recursiveRef` are refused.
- Regular-expression patterns: at most 512 characters, with no nested repetition such as `(a+)+`.
- Changelog: at most 4,000 characters.
- Refusals start with *Schema refused: …*. A secret-screening check can block a publish, or ask you
  to acknowledge a warning.

## Rate limits

When you hit a rate limit, Zekt responds with **HTTP 429** and these headers:

- `Retry-After`: seconds to wait;
- `X-RateLimit-Limit`;
- `X-RateLimit-Remaining: 0`.

The body looks like:

```json
{ "error": "Rate limit exceeded", "bucket": "…", "retryAfter": 30, "requestId": "…" }
```

How requests are counted:

- Signed-in callers are counted per user, anonymous callers per IP address.
- Counting is per calendar minute, with a burst limit of 10 per second.
- Endpoints in the same family share a counter.

| Area | Typical limit per minute |
| --- | --- |
| Most changes | 60 |
| Member management | 20 |
| Directory | 120 |
| Replay history and trust lookups | 120 |
| Public registry and avatars | 30 per IP |
| Zekt Action event submission | 30 per provider repository |
| MCP | 30 per token. Every tool call counts, including reads. |

Two areas use a different body:

- **Zekt Action** event submission: `{"error":"rate_limit_exceeded","retryAfterSeconds":N}`.
- **MCP**: `{"error":"Rate limit exceeded (<type>)","retryAfter":N}`.

Honour `Retry-After` and back off before retrying.
