Zekt connects GitHub Actions workflows across repository and organization boundaries. A workflow in
one repository can trigger workflows in other repositories, and nobody shares tokens or repository
access.

Zekt delivers each event to a receiving repository as a GitHub `repository_dispatch` event, and
records the delivery. Delivery is at-least-once. You manage everything in the web console at
[www.zekt.dev](https://www.zekt.dev).

## The building blocks

| Component | What it is |
| --- | --- |
| **Zekt Core** | Providers, consumers, the Directory and access approval. |
| **[Zekt Action](/zekt-docs/provider/zekt-action/)** | The GitHub Action `zekt-dev-org/zekt-action@v3`. Use it to attach a payload to an event, submit orchestration requests, and report a consumer service's outputs. |
| **[Zekt Analytics](/zekt-docs/add-ons/analytics/)** | Add-on. |
| **[Zekt Shield](/zekt-docs/add-ons/shield/)** | Add-on. |
| **[Zekt Chainlink](/zekt-docs/add-ons/chainlink/)** | Add-on. |

For prices, see [zekt.dev/zekt-pricing](https://www.zekt.dev/zekt-pricing.html).
