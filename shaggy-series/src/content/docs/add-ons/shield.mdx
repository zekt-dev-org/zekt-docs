Zekt Shield is an add-on with three parts:

- **End-to-end encryption**: payloads are encrypted in the provider's workflow, and only the consumer
  can decrypt them. Zekt routes ciphertext and never has the private key.
- **Redaction Guard**: scans outgoing payloads for secrets and masks or withholds them.
- **Doctrine**: allow-lists that a Shepherd account sets for its Disciples.

Find it under sidebar → **Shield**, with the tabs Provider Shield, Consumer Keys, Redaction Guard and
Doctrine. Shield is shown to accounts that pay their own bill, not to Disciple accounts.

## End-to-end encryption

### Consumer: upload your public key

<Steps>

1. Generate an RSA key pair on your own machine, for example with `openssl genrsa 4096`. Use
   4096 bits (recommended) or at least 2048.
2. Go to **Shield → Consumer Keys** and upload **only the public key**, in PEM format. One key covers
   all of your account's subscriptions. If you paste a private key, it's rejected.
3. Store the private key as a GitHub Actions secret in your consumer repository. It never leaves you.

</Steps>

The screen shows your key's fingerprint and age, and recommends rotating it after 90 days. Uploading
a key is free.

### Provider: turn on Shield and encrypt

<Steps>

1. Go to **Shield → Provider Shield** and turn it on for the provider repository.
2. In the workflow, set `shield: true` on the [Zekt Action](/zekt-docs/provider/zekt-action/). The
   payload is encrypted in your workflow, before it reaches Zekt.
3. Optionally, mark the service **Require Shield (Strict Mode)** in its service description. Then
   every payload must be encrypted, and consumers must have uploaded a key to subscribe.

</Steps>

| Error | Meaning |
| --- | --- |
| *SHIELD_NOT_ENABLED…* | `shield: true` was set, but Shield isn't on for the repository. |
| *SHIELD_ENFORCEMENT…* | The service requires encryption, and the payload wasn't encrypted. |
| **Shield Not Enabled** | You tried to mark a service *Require Shield* without Shield on the repository. |

### Consumer: decrypt

The consumer decrypts in its own workflow, with its private key.

### What Shield covers

- It protects the **payload** only. Run metadata (workflow name, branch, conclusion, timestamps) is
  still visible to Zekt and to the consumer.
- It doesn't cover orchestration step inputs and outputs.
- Zekt can't read or show an encrypted payload. Archived and replayed Shield events stay encrypted.

## Redaction Guard

Redaction Guard is one setting for the whole account, separate from the per-repository Shield
toggle. Configure it in **Shield → Redaction Guard**. It scans each outgoing provider payload,
field by field.

**Patterns:** built-in patterns for GitHub tokens, Stripe keys, AWS keys, Azure keys, JWTs and generic
API keys. You can add your own, as regular expressions or literal text. A regular expression must
compile and run quickly, or it's refused (`INVALID_PATTERN`).

**Actions:**

| Action | What consumers get |
| --- | --- |
| **Redact and log** (default) | Matching values replaced with `***REDACTED***`. |
| **Block** | The payload is withheld: `zekt.payload` arrives as `null`. |
| **Log only** | The payload unchanged. The match is only logged. |

- After redacting, Redaction Guard scans again. If anything is still found, the payload isn't
  delivered.
- If a scan can't finish, the payload is withheld, unless you chose *Log only*.
- Each delivery shows what Redaction Guard did: clean, redacted, withheld, failed or log-only.
- Logs record the pattern name, never the matched value, and are kept for 90 days.
- Orchestration steps and subscriber-fired sends aren't scanned.

## Doctrine (Shepherd accounts)

Doctrine lets a [Shepherd](/zekt-docs/operate/members/#flock-shepherd-and-disciple-accounts) limit
what its Disciples can connect to:

- **Provider rules**: which providers a Disciple may request access from, optionally narrowed to
  specific services.
- **Consumer rules**: which consumers a Disciple may approve.

Doctrine is off by default, and an empty rule list allows everything. It's checked when a Disciple
requests or approves access. Refusals are recorded and kept for 90 days. Doctrine has no separate
fee.

## Cost

The provider pays: a monthly fee per Shield-enabled repository (a Chainlink repository counts once),
plus usage. See [zekt.dev/zekt-pricing](https://www.zekt.dev/zekt-pricing.html).
