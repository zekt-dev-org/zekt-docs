You manage Zekt in the web console at [www.zekt.dev](https://www.zekt.dev). You can also work with
it from outside the console:

- **[VS Code extension](#vs-code-extension)**: manage Zekt from your editor.
- **[MCP](#mcp)**: connect AI assistants and other MCP clients to Zekt through the Model Context
  Protocol.

Both sign in with an **API token**. Programmatic access is through MCP. The REST endpoints the console
uses aren't a public API.

## API tokens

Manage tokens under **Profile → API Access**, which has three tabs: **Generate Tokens**, **Active
Tokens** and **MCP Setup Docs**. API Access is shown to accounts that pay their own bill.

<Aside type="note">
	Today only the **account owner** (the GitHub login the account belongs to) can create, list or
	revoke tokens.
</Aside>

### Create a token

<Steps>

1. Go to **Profile → API Access** and create a new token.
2. Give it a name that says where it will be used, for example `vscode-laptop` or `release-pipeline`.
3. Choose its **scopes** (see below).
4. Choose an expiry: **30**, **90** (the default), **180** or **365 days**, or **No expiration**.
5. Copy the token. **It's shown only once.** Store it in a secret store, such as GitHub Secrets or
   your editor's secret storage.

</Steps>

### Scopes

Choose each scope separately. Scopes don't include each other.

| Scope | Allows |
| --- | --- |
| `read` | Reading repositories, connections and delivery status. Any valid token can read. |
| `dispatch` | Dispatching events. |
| `replay` | Replaying past events and webhooks. |
| `manage` | Creating and changing configuration. |

A call that needs a scope the token doesn't have is rejected with **403**.

Give each token only the scopes it needs. A token that only reads delivery status should have no
other scopes.

### Expiry and revocation

- The token list shows each token as **Active**, **Expired** or **Revoked**, with the date it was
  last used.
- Revoking takes effect immediately.
- An expired or revoked token gets *Invalid or expired API token*.

### Tokens that create tokens

A token can create new tokens, but only with these limits:

- the new token's scopes must be a subset of its own;
- it must have an expiry, no later than the creating token's own expiry.

You can only create a token with **No expiration** while signed in to the console.

### Tokens for Flock members

A Shepherd account can create and revoke tokens on behalf of an accepted Disciple account. See
[Members and Flock](/zekt-docs/operate/members/#flock-shepherd-and-disciple-accounts).

## VS Code extension

Install **Zekt — Cross-Org Event Dispatch** (`zekt-dev-org.zekt-mcp`) from the
[VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=zekt-dev-org.zekt-mcp). It
needs VS Code 1.95 or later.

### Sign in

<Steps>

1. [Create an API token](#create-a-token) in **Profile → API Access**.
2. In VS Code, run **Zekt: Sign In** (or **Zekt: Configure API Token**) and paste the token. There's no
   browser sign-in.
3. The extension checks the token. Your account must be active, with a payment method on file.

</Steps>

The token is kept in VS Code's secret storage, which uses your operating system's credential store.
**Zekt: Sign Out** clears it, and offers to remove the MCP configuration.

### MCP configuration

After you sign in, the extension adds a `zekt` server to `.vscode/mcp.json` in your first workspace
folder. It does this automatically (the `zekt.autoConfigureMcp` setting, on by default), or when you run
**Zekt: Setup MCP Server Configuration**. Other servers already in the file are kept.

<Aside type="danger" title="The MCP file holds your token in plain text">
	`.vscode/mcp.json` contains your API token. The extension adds it to `.gitignore` only if a
	`.gitignore` already exists. Make sure `.vscode/mcp.json` is git-ignored, and never commit it.
</Aside>

### Commands

| When | Commands |
| --- | --- |
| Always | **Zekt: Configure API Token**, **Zekt: Setup MCP Server Configuration**, **Zekt: Open Dashboard** |
| Signed out | **Zekt: Sign In**, **Zekt: Sign Up for Zekt** |
| Signed in | **Zekt: Sign Out**, **Zekt: Check Delivery Status** (`Ctrl+Shift+Z S`), **Zekt: List Subscribers**, **Zekt: Browse Provider Directory**, **Zekt: Replay Event**, **Zekt: Event History**, **Zekt: Subscribe to Provider**, **Zekt: Account Summary**, **Zekt: Manage Workflows**, **Zekt: Manage Services**, **Zekt: Create Service**, **Zekt: List Pending Access Requests**, **Zekt: Browse Service Catalog**, **Zekt: List My Consumer Repos**, **Zekt: List My Subscriptions** |

The Zekt sidebar has these views: **Account**, **Providers**, **Directory**, **Consumers**, **Recent
Activity** and **Approve & Reject**. Right-click items to whitelist or blacklist a workflow, connect a
workflow to a service, publish or unpublish a service and set its visibility, remove a service, revoke
a subscriber, subscribe or unsubscribe, and approve or deny requests. The status bar shows whether
you're connected.

The extension can't send events. Events are sent only by the [Zekt Action](/zekt-docs/provider/zekt-action/)
in GitHub Actions.

## MCP

Zekt is a remote MCP server over Streamable HTTP. Each request is independent (stateless).

### Connect a client

<Steps>

1. [Create an API token](#create-a-token) in **Profile → API Access → Generate Tokens**. API Access is
   available to accounts that manage their own billing, not to Disciple accounts.
2. Copy the server address from **Profile → API Access → MCP Setup Docs**.
3. Add the server to your client, sending the token in an `Authorization: Bearer` header. Tokens in
   the URL are refused. For VS Code or Cursor:

   ```json
   {
     "servers": {
       "zekt": {
         "type": "http",
         "url": "<address from MCP Setup Docs>",
         "headers": { "Authorization": "Bearer <your zekt_ token>" }
       }
     }
   }
   ```

</Steps>

Keep any file that holds your token out of version control.

### What you can do through MCP

Reading needs only a valid token. Every change needs the `manage` scope.

| Area | Tools |
| --- | --- |
| Account | Account summary. |
| Directory | Browse the Directory and services. |
| Provider services | List and create services, set visibility, list and whitelist workflows. |
| Access | Pending requests, approve, deny, subscribers, revoke. |
| Consumer | Repositories, subscriptions, subscribe (by service ID), unsubscribe. |
| Events | Delivery status, event history (up to 50 per call), replay (by the original provider only). |

Three read-only resources are also available: account summary, provider repositories and consumer
repositories.

<Aside type="caution" title="Dispatching isn't available through MCP">
	To send events, use the [Zekt Action](/zekt-docs/provider/zekt-action/) in a workflow.
</Aside>

### Errors

| Response | Meaning |
| --- | --- |
| 401 | The token is invalid, expired or revoked. |
| 403 (JSON-RPC `-32003`) | The token lacks a scope (the error names it), or your account can't start new work, for example a replay while a payment is overdue (see [billing](/zekt-docs/billing/how-billing-works/#when-a-payment-fails)). |
| 503 (JSON-RPC `-32603`) | Zekt couldn't check your account's standing. Retry. |
| 429 | Rate-limited. Wait for `Retry-After`. |

### Rate limits

Every request to the MCP endpoint counts, including housekeeping such as `tools/list`:

- 30 per minute and 10 per second, per token;
- plus a shared limit of 60 changes per minute per user, which also counts your console actions. A
  busy agent can slow down your own changes in the console.

See [Limits](/zekt-docs/reference/limits/#rate-limits).

## Usage and cost

MCP tool calls and resource reads are billed as usage. Connection housekeeping isn't billed:
initialising, pinging, list calls and notifications. See
[zekt.dev/zekt-pricing](https://www.zekt.dev/zekt-pricing.html), and track usage under
**Management → Billing → Current Usage**.
