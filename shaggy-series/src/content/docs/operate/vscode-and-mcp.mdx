You manage Zekt in the web console at [www.zekt.dev](https://www.zekt.dev). You can also work with
it from outside the console:

- **MCP**: connect MCP clients to Zekt through the Model Context Protocol.
- **VS Code extension**: available on the
  [VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=zekt-dev-org.zekt-mcp).
  It sets up an MCP connection to Zekt for you.
- **Programmatic use**: start orchestrations and replays from your own tooling.

All of them sign in with an **API token**.

## API tokens

Manage tokens under **Profile → API Access**.

<Aside type="note">
	Today only the **account owner** (the GitHub login the account belongs to) can create, list or
	revoke tokens.
</Aside>

### Create a token

<Steps>

1. Go to **Profile → API Access** and create a new token.
2. Give it a name that says where it will be used, for example `vscode-laptop` or `release-pipeline`.
3. Choose its **scopes** (see below).
4. Choose an expiry: **30**, **90** (the default), **180** or **365 days**, or **No expiration**.
5. Copy the token. **It's shown only once.** Store it in a secret store, such as GitHub Secrets or
   your editor's secret storage.

</Steps>

### Scopes

Choose each scope separately. Scopes don't include each other.

| Scope | Allows |
| --- | --- |
| `read` | Reading repositories, connections and delivery status. Any valid token can read. |
| `dispatch` | Dispatching events. |
| `replay` | Replaying past events and webhooks. |
| `manage` | Creating and changing configuration. |

A call that needs a scope the token doesn't have is rejected with **403**.

Give each token only the scopes it needs. A token that only reads delivery status should have no
other scopes.

### Expiry and revocation

- The token list shows each token as **Active**, **Expired** or **Revoked**, with the date it was
  last used.
- Revoking takes effect immediately.
- An expired or revoked token gets *Invalid or expired API token*.

### Tokens that create tokens

A token can create new tokens, but only with these limits:

- the new token's scopes must be a subset of its own;
- it must have an expiry, no later than the creating token's own expiry.

You can only create a token with **No expiration** while signed in to the console.

### Tokens for Flock members

A Shepherd account can create and revoke tokens on behalf of an accepted Disciple account. See
[Members and Flock](/zekt-docs/operate/members/#flock-shepherd-and-disciple-accounts).

## Usage and cost

MCP calls are billed as usage. See [zekt.dev/zekt-pricing](https://www.zekt.dev/zekt-pricing.html),
and track them under **Management → Billing → Current Usage**.
